# Logging Convention — מהמקור (MEH-240)

## Overview

All backend logging goes through **structlog**. Each log line in production
is a JSON object with a `request_id` field injected automatically via the
`X-Request-ID` correlation-ID middleware.

## Getting a logger

```python
import structlog
logger = structlog.get_logger(__name__)
```

Use keyword arguments — not f-strings or `%s` format strings:

```python
# good
logger.warning("push notification failed", user_id=user_id, error=str(e))

# bad
logger.warning(f"push notification failed for {user_id}: {e}")
```

## Log levels

| Level | When to use |
|---|---|
| `logger.debug(...)` | Expected degraded mode (env var missing, feature intentionally off) |
| `logger.info(...)` | Normal operation milestones |
| `logger.warning(..., exc_info=True)` | Unexpected failure that degrades a feature but doesn't crash the request |
| `logger.error(..., exc_info=True)` | Unrecoverable error or data integrity concern |
| `logger.exception(...)` | Equivalent to `logger.error(..., exc_info=True)` — use inside `except` blocks |

## Silent-failure patterns — always add a log call

### Config / env-var missing (DEBUG)

```python
if not settings.vapid_private_key:
    logger.debug("push notifications disabled", reason="VAPID_PRIVATE_KEY not set")
    return
```

### Bare `except` that swallows a real error (WARNING)

```python
try:
    result = db.query(...)
except Exception as e:
    logger.warning("cache query failed, returning empty result", exc_info=True)
    result = []
```

### State skip — buyer has no phone, etc. (DEBUG)

```python
if not buyer or not buyer.phone:
    logger.debug("SMS skipped", reason="buyer has no phone", click_id=click.id)
    return
```

## Required kwargs

| Situation | Required kwarg |
|---|---|
| Config missing | `reason=` |
| Exception caught | `exc_info=True` (or use `logger.exception`) |
| Resource skip | `reason=` + identifying ID |
| External service failure | `service=` + `exc_info=True` |

## Production format (Railway, LOG_FORMAT=json)

```json
{
  "event": "push notification failed",
  "request_id": "01HXK9...",
  "level": "warning",
  "logger": "app.services.push",
  "timestamp": "2026-04-22T14:03:11.204Z",
  "user_id": "abc123",
  "exc_info": "Traceback ..."
}
```

## Dev format (LOG_FORMAT=console)

Plain colored output with timestamp, level, logger name, event, and kwargs.

## Environment variables

| Variable | Default | Values |
|---|---|---|
| `LOG_FORMAT` | `console` | `json` (Railway) / `console` (dev) |
| `LOG_LEVEL` | `INFO` | `DEBUG` / `INFO` / `WARNING` / `ERROR` |

## Sensitive field redaction

The following field names are automatically redacted to `[REDACTED]` regardless
of log level:

`password`, `token`, `secret`, `authorization`, `access_token`,
`refresh_token`, `api_key`

Never log raw JWT tokens, passwords, or API keys as positional args — the
redaction processor only checks keyword argument names.

## Request correlation

Every request gets an `X-Request-ID` header (UUID). The header is:
- Generated by `CorrelationIdMiddleware` if the client doesn't send one.
- Forwarded as-is if the client sends `X-Request-ID`.
- Added to every log line automatically via `_add_correlation_id` processor.
- Returned in the response `X-Request-ID` header so Railway logs and
  frontend logs can be correlated by request.

To find all logs for a single request in Railway:
```
filter: request_id = "01HXK9..."
```
