# MEH-2894 — run the action map's full guard on the PRs that can stale it

**Staged for Sapir. CC cannot apply this**: `.github/workflows/**` is
mechanically denied (`.claude/settings.json` `permissions.deny`).

**As of 2026-11-10**, against `pr-checks.yml` at `origin/staging`
(`git apply --check` clean, YAML parsed). Line numbers drift — match on content.

## Why

`docs/release/action-map.md` is generated by `scripts/release/action_map.py`.
Two guards keep it honest:

| Guard | Where | Runs on | Checks |
|---|---|---|---|
| `scripts/checks/action-map-drift-guard.sh` | **Repo guards** (always) | every PR | stdlib only: the doc's sha256 manifest (hand edits), every `covered` citation still points at a call / 401-403 / `.goto(`, the «Pages» section, the business-tool ids, the audit rows |
| `tests/test_action_map_complete.py` | **pytest** job | PRs matching the `backend` path filter | everything above **plus** the API-route table (needs FastAPI) |

Today the `backend` filter is `backend/**`, `tests/**` and
`scripts/check_api_contract.py`. So a PR that changes **only** the generator,
or only `business-features.js` / the audit in a way the static tier cannot
fully judge (e.g. a tool's codeRef now pointing at a router), never runs the
full tier. This patch adds those five paths. It does **not** add
`frontend/app/**` or `frontend/e2e/**`: the static tier already regenerates
the «Pages» section on every PR, and adding them would run the 3-shard pytest
on every frontend PR.
