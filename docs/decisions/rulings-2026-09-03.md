## 2. MEH-1892 — `<bdi>` / `unicode-bidi: isolate` · ⛔ **REFUTED**

**Refuting command:** is the defect an inline fragment, or the document's own direction?

```
frontend/app/globals.css:168-169     html { direction: rtl; }      ← unconditional
grep 'html\[dir'  frontend/app/globals.css   →  NO MATCH
frontend/app/[locale]/layout.js:202  const dir = locale === "he" ? "rtl" : "ltr";
frontend/app/[locale]/layout.js:205  <html lang={locale} dir={dir} …>
```

**There is no English fragment to isolate.** The layout already computes the correct
base direction and puts `dir="ltr"` on `<html>` for `/en`; an unconditional CSS rule
on the root element then overrides it, so the **whole document** renders RTL. The
element whose direction is wrong is `<html>` itself.

`<bdi>` and `unicode-bidi: isolate` isolate an *inline run of opposite-direction text
inside a paragraph*. Applied here they would wrap something inside a document whose
base direction is still wrong, and change nothing observable. That is the MEH-1721
P7 F-1 shape exactly — a prescribed edit that applies cleanly, goes green, closes the
card, and leaves `/en` broken.

**On the W3C anchor, which is sound but aimed elsewhere.** "Isolate inline bidi
content, never restructure" is guidance for mixed-direction runs *within* a block.
"Never `dir="ltr"` on block elements" warns against hacking inline bidi by wrapping
blocks. Neither says a page must not carry its own base direction on `<html>` — W3C
prescribes precisely that, which is what `layout.js:202` already does correctly. The
ruling and the codebase are not in conflict about bidi; they are about different
defects.

**What I need before building:** one line saying which is intended —

- **(a)** the `/en` document-direction defect the card was opened on, whose minimal
  fix is scoping the root rule (`html` → `html[dir="rtl"]`, one line), or
- **(b)** a genuine inline-fragment defect somewhere specific, in which case `<bdi>`
  is right and I need the surface, because I could not find one that this ruling fits.

I have not implemented either. **This is the whole reason the refutation step exists**,
and it is the one case where guessing costs more than asking.
