# SEO / Metadata Completeness Audit — 2026-06-13

> Overnight batch #3 — Task 3. **Report only — no code changes.**
> Branch: `feature/audit-seo-meta`. Scope: every App-Router route under
> `frontend/app/[locale]/**` + `frontend/app/sitemap.js` + `frontend/public/robots.txt`.
> Signals audited per route: **title · meta description · canonical · hreflang ·
> OpenGraph · Twitter · JSON-LD · robots/noindex correctness**.

## TL;DR

The metadata foundation is **strong and well-factored** — two shared helpers
(`lib/seo.js` for producer content, `lib/i18n-seo.js` for locale-aware
`alternates`) mean canonical + hreflang are emitted **consistently on all 34
routes that define their own metadata**. Private/auth pages correctly carry
`robots: { index: false }`, and dynamic detail pages correctly noindex their
404 branches while still emitting hreflang.

The gaps are concentrated in **four areas**:

1. **Sitemap ↔ noindex conflict** — `sitemap.js` submits 4 URLs that the pages
   themselves mark `noindex` (Google "Submitted URL marked noindex" errors).
2. **Twitter cards are never customized per page** — every route inherits the
   generic site-level card from the layout.
3. **JSON-LD coverage is thin** — only producer detail + recipes + one FAQ page.
   The **homepage has no Organization / WebSite / SearchAction** structured data,
   and events/experiences/group-buys detail pages emit none.
4. **A handful of private/utility routes are indexable** (`/messages`,
   `/rate/[token]`, `/experiences/new`, `/register/producer`) and a handful of
   indexable public pages are **missing from the sitemap** (`/experiences`,
   `/group-buys`, the business guides, dynamic event/experience/group-buy details).

There is also a **stale `/en` policy signal**: code comments reference a
`Disallow: /en/` in `robots.txt` that **does not exist** in the current file —
`/en` is fully indexable today (self-canonical + hreflang). See Finding G.

## How metadata is built (baseline)

| Layer | File | What it sets |
|---|---|---|
| Locale layout | `app/[locale]/layout.js:42-103` (`BASE_METADATA`) + `:105-156` (`generateMetadata`) | `metadataBase`, title template `%s \| מהמקור`, description, keywords, icons/manifest, **OpenGraph**, **Twitter** (`summary_large_image`), `robots: {index:true, follow:true}`, `alternates: buildAlternates("/", locale)` |
| Producer content | `lib/seo.js` | `buildTitle`, `buildDescription`, `ogImage` (1200×630), `buildPageUrl` (slug-preferred), `buildJsonLd` (`@graph`: FoodEstablishment + BreadcrumbList + WebPage + WebSite + Organization), `buildProducerMetadata` |
| i18n SEO | `lib/i18n-seo.js` | `urlForLocalePath`, `buildAlternates` (self-canonical + `he-IL`/`en`/`x-default` hreflang), `buildEntityTitle` |
| Sitemap | `app/sitemap.js` | per-locale `<url>` + inline `<xhtml:link>` hreflang |
| Robots | `public/robots.txt` | static allow/disallow + sitemap pointer |

**Inheritance rule (Next.js):** routes without their own `generateMetadata`
inherit the layout's — including `alternates: buildAlternates("/", …)`, i.e.
**canonical → homepage**. Routes that define metadata shallow-merge over the
layout (so a route that sets `openGraph` but not `twitter` keeps the layout's
generic Twitter card).

## Findings (detailed, by category)

### A. Sitemap ↔ noindex conflict — **HIGH**
`sitemap.js:46,45,48,49` submit `/login`, `/register`, `/contact`, `/search`,
but each page sets `robots: { index:false }` (`login:28`, `register:28`,
`contact:30`, `search:29`). Google Search Console reports these as **"Submitted
URL marked 'noindex'"** coverage errors and wastes crawl budget.
**Fix direction:** remove these four from the sitemap (they're auth/thin), OR
drop their `noindex` if they're genuinely wanted in the index. Pick one — the
two signals must agree.

### B. Twitter cards never customized — **MEDIUM**
No route sets a page-level `twitter` object (grep: 0 hits across `app/[locale]/**/page.*`).
Every page inherits `layout.js:85-90,148-152` — so the Twitter card title/description
is the **site-level string on every share**, including producer, event, and
recipe pages that have rich per-page OG. Twitter/X falls back to OG for most
fields, so impact is partial, but `twitter:title`/`twitter:description` are
generic site-wide.
**Fix direction:** mirror the per-page `openGraph` into `twitter` in
`buildProducerMetadata` + the event/experience/recipe metadata builders.

### C. Homepage has no structured data — **HIGH (AEO)**
`app/[locale]/page.js` defines no JSON-LD. The `WebSite` + `Organization` graph
nodes only ship on producer pages (`lib/seo.js:297-315`). The homepage — the
strongest candidate for **`Organization`** (logo, sameAs) and **`WebSite` +
`SearchAction`** (Google sitelinks search box) — emits none.
**Fix direction:** add an `Organization` + `WebSite`(`potentialAction:SearchAction`)
JSON-LD block to the home route (reuse the nodes already in `lib/seo.js`).

### D. Thin JSON-LD coverage on public detail pages — **MEDIUM**
- `/events/[id]` — no `Event` schema (has `og:type=article` only). Event rich
  results (date/location/offers) unavailable.
- `/experiences/[id]`, `/group-buys/[id]` — no schema.
- `/producers` — no `ItemList`/`CollectionPage`.
- Business guides (`/about/for-businesses/guides/*`) — no `Article`/`HowTo`.
**Fix direction:** add `Event` to event details (highest ROI), `ItemList` to
the directory, `Article` to the guides.

### E. `/producer/[id]` canonical does not point at the slug URL — **MEDIUM**
`producer/[id]/page.js:24` sets `alternates = buildAlternates('/producer/${id}', locale)`
→ **self-canonical to the numeric URL**, while `buildProducerMetadata` /
`buildPageUrl` prefer the slug (`lib/seo.js:86-91`) and the sitemap emits the
**slug** URL (`sitemap.js:66`). For a producer that has a slug, the same content
is then canonical-reachable at **both** `/producer/[id]` (self-canonical) and
`/{slug}` (in sitemap) → duplicate-URL signal.
**Fix direction:** when a slug exists, `/producer/[id]` should canonical to the
slug URL (or 301-redirect to it), not self-canonical.

### F. Private/utility routes indexable — **MEDIUM**
`/messages` (no `robots`), `/rate/[token]` (no metadata), `/ref/[code]` (no
metadata), `/experiences/new`, `/register/producer` are all indexable. The
metadata-less ones additionally **canonical to `/`** via the layout fallback.
`/rate/[token]` is the most sensitive (tokenized URL).
**Fix direction:** add `robots:{index:false}` to each; or for `rate`/`ref`,
add a minimal `generateMetadata` returning `noindex` so they stop canonicalizing
to the homepage.

### G. Stale `/en` robots signal — **LOW (verify intent)**
`components/LanguageToggle.jsx:30` (header comment) and prior session notes refer
to a **`Disallow: /en/` in robots.txt** that **does not exist** in the current
`public/robots.txt` (only `/admin/`, `/api/`, `/settings`, `/favorites`,
`/producer/dashboard/`, `/login`, `/register` are disallowed). Current `/en`
state: **fully indexable** — `robots:{index:true}` (layout) + self-canonical to
the `/en` URL + `en`/`he-IL`/`x-default` hreflang. This is correct multilingual
SEO **if** EN is meant to be indexed. **Decision needed:** confirm `/en` should
be indexed (current behavior) and delete the stale "Disallow /en/" references,
**or** if EN is not launch-ready, add the `Disallow` + `noindex`. The two signals
(code comments vs. actual config) currently disagree.

### H. Admin/dashboard rely on robots.txt only (no meta noindex) — **MEDIUM**
Because `admin/layout.js` and the dashboard pages are `"use client"`, none can
export `robots`. Index protection is **robots.txt Disallow + client auth**. A
crawler that ignores robots.txt (or a leaked deep link) gets `index:true` +
canonical → `/`. Server-render a tiny metadata shim (a `layout.js` server
wrapper) to emit `robots:{index:false}` for `/admin/**` and
`/producer/dashboard/**`.

### I. Indexable public pages missing from sitemap — **MEDIUM**
`sitemap.js:39-51` static list omits `/experiences`, `/group-buys`,
`/about/process`, `/about/for-businesses` (+ guides), `/accessibility`,
`/privacy`, `/terms` is present. Dynamic detail pages **`/events/[id]`,
`/experiences/[id]`, `/group-buys/[id]`** are also absent (only producer
details are dynamically enumerated, `:56-72`). These indexable pages are
discoverable only via internal links, not the sitemap.

### J. robots.txt sitemap host — **LOW (verify)**
`public/robots.txt` hardcodes `Sitemap: https://mehamakor.co.il/sitemap.xml`
while `lib/i18n-seo.js` comments call the canonical host `mehamakor.online`.
Confirm the production apex (`mehamakor.co.il` per `docs/DEPLOYMENT.md`) matches
the `SITE_URL` that `sitemap.js` actually emits, so sitemap entry hosts and the
robots.txt pointer agree.
