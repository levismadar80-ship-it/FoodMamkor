## Vector 2 — LTR arrows (←) in Hebrew context

Rule: `←` (U+2190) flagged in RTL/Hebrew context; RTL should prefer `→` or a
proper directional glyph.

**Key finding:** the project is **internally split**. `he.json` contains:
- **`←` (leftwards): 32 occurrences** (listed below)
- **`→` (rightwards, RTL-correct forward): ~26 occurrences** — e.g.
  `"register_cta": "הצטרפו →"` (162), `"next": "הבא →"` (288),
  `"submit": "הצטרפי →"` (290), `"register": "להרשמה →"` (1937),
  `"open_mail_fallback": "פתיחת מייל ישירות →"` (2483),
  `"support_cta": "דברי איתנו →"` (3535), `"edit_profile_link": "ערכי פרופיל עסק →"` (3547).

So two *different* arrow directions are used for the **same affordance type**
(forward/continue CTAs and pagination-next): some say `הבא →`, others say
`← הקודם`/`לכל האירועים ←`. This is the real bug — inconsistency — and it
cannot be fixed piecemeal without a single canonical rule (OQ3).

## OPEN QUESTIONS for Sapir

1. **WhatsApp canonical spelling.** `וואטסאפ` (12×) vs `ווטסאפ` (11×) — no
   dominant form; `וואצאפ`/`ווצאפ` are absent. Which is canonical? Also: Latin
   `WhatsApp` appears inside Hebrew copy (260, 2722) — allow Latin, or always
   Hebraize? → `COPY_STYLE.md` marks this **PENDING Sapir**.

2. **Email canonical spelling.** `אימייל` (33×) vs `מייל` (~51× standalone).
   Both grammatical. Pick the canonical field-label form (`אימייל`?) and
   decide whether prose `תיבת המייל` / `כתובת מייל` is an allowed exception or
   must normalize. → `COPY_STYLE.md` marks this **PENDING Sapir**.

3. **Directional arrow convention (the load-bearing one).** `he.json` uses
   **`←` 32× AND `→` ~26×** for the same affordance class — two different
   directions for "forward/continue" and "next". For a Hebrew RTL UI the
   semantically-correct forward glyph is `→` and back is `←`, but current usage
   mixes them. Pick ONE rule:
   - (a) **RTL-aware** — `→` = forward/continue/next, `←` = back/previous, and
     normalize all ~38 `←` strings + audit the `→` ones for correct semantics
     (recommended for correctness), or
   - (b) keep `←` as a flat house-style for everything (then the ~26 `→`
     strings become the drift to normalize instead).
   Until decided, no arrow string should be fixed piecemeal. Gallery prev/next
   (`ImageGallery.jsx`, `Lightbox.jsx`) must apply the chosen rule to **both**
   directions.
