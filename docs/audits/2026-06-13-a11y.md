# Accessibility Audit — 2026-06-13 (MEH-230, 4/7)

**Scope:** Static a11y audit of `frontend/app/**` + `frontend/components/**`
across 8 manual vectors, plus an axe-core regression net (see
`frontend/e2e/flows/12-axe-a11y.spec.ts`). **Report + net only** — no UI/brand/
focus-style fixes were made in this PR. Removals are documented, not fixed.

**Method:** grep + per-file read across 211 frontend `.jsx/.js/.tsx` files;
contrast ratios computed with the WCAG 2.x relative-luminance formula against
the canonical tokens in `frontend/tailwind.tokens.json`. Findings cross-checked
against file:line (per meta-pattern #1 — verify agent claims with evidence).

**Headline:** The codebase already has strong a11y hygiene (prior a11y work
shows: icon buttons carry `aria-label`, modals largely implement
dialog+ESC+focus-trap, RTL uses logical props with documented `rtl-ok`
exceptions). **No CRITICAL or SERIOUS findings.** The open backlog is
MODERATE-tier: color contrast and focus-indicator removals.

**Post-merge axe addendum (live run caught what the static grep missed):** the
axe net surfaced **two** real `serious` ARIA-name findings the file:line pass
above did not:

1. `ProducerCard.jsx:366` — `aria-label` on a `<span>` with no `role`
   (`aria-prohibited-attr`). **Fixed** in this PR (`role="img"`).
2. **Leaflet map markers** (`/` homepage preview + `/map`) — rendered as
   `<div role="button" tabindex="0">` divIcons with **no accessible name**
   (`aria-command-name`). Real bug; the proper fix wires each business name into
   the marker `aria-label` in `MapComponent`/`MapClient` (central component) →
   **deferred to a follow-up sub-MEH**. The axe net `.exclude(".leaflet-marker-icon")`
   so it stays green and still catches every other map a11y issue.

## Vector 8 — RTL reading-order (VoiceOver/TalkBack)

App is RTL-first and overwhelmingly uses logical props (`ms-/me-/ps-/pe-/
start-/end-`). Physical props appear only at **documented `rtl-ok` exception
sites** (carousel arrows, map overlays pinned to physical corners,
`dir="ltr"` password-eye toggles, horizontal-center idiom
`left-1/2 -translate-x-1/2`). Per `.claude/rules/rtl.md` these exceptions
**stay**. Two minor doc gaps (missing the `rtl-ok` comment, not a behavior bug):

| File:Line | Concern | Severity |
|---|---|---|
| `frontend/components/CategorySelector.jsx:36` | `pr-9 pl-3` physical padding, no `rtl-ok` comment (intentional for the 🔍 span) | MINOR |
| `frontend/app/[locale]/settings/page.jsx:472,479,518,525` | password-eye `pr-11 pl-3` / `right-3` without `rtl-ok` annotation (matches the documented eye-toggle exception elsewhere) | MINOR |

No DOM-order-vs-visual-order inversions found (no stray `flex-row-reverse` /
`order-` reordering meaningful content). Reading order is sound for AT.
