# Authenticated-only surfaces — no SEO value, may leak PII in referer logs
# MEH-1955 gap-check: /register/producer is an INDEXABLE acquisition landing
# page the sitemap submits (sitemap.js, priority 0.7). `Disallow: /register`
# below prefix-matches it, so without this Allow the sitemap advertised a URL
# robots forbade — a GSC "submitted URL blocked by robots.txt" error and an
# uncrawlable landing page. Longest-match wins (Google/Bing), so the more
# specific Allow overrides the shorter Disallow.
Allow: /register/producer
Disallow: /admin/
Disallow: /api/
Disallow: /settings
Disallow: /favorites
Disallow: /producer/dashboard/
Disallow: /login
Disallow: /register

# AI SEARCH crawlers — explicitly allowed, with the same Disallows as `*`
# (MEH-2786). Search is not training: OpenAI and Anthropic ship SEPARATE
# user-agents for the two jobs, so the GPTBot / ClaudeBot blocks above say
# nothing about OAI-SearchBot, Claude-SearchBot or Claude-User. Per
# Anthropic's crawler docs, blocking Claude-SearchBot or Claude-User can
# reduce our visibility in Claude's search answers — so they are named here
# rather than left to `*`.
#
# WHY EACH GROUP REPEATS THE DISALLOWS, AND MUST KEEP REPEATING THEM:
# a crawler obeys exactly ONE group — its most specific match — and ignores
# `*` entirely once a group names it. A group holding only `Allow: /` would
# therefore hand that bot /admin/, /api/, /settings, /favorites and
# /producer/dashboard/. The two `Allow: /register/producer` lines are part of
# the mirror too: with `Allow: /` present, the longer `Disallow: /register`
# still wins on longest-match and would make the MEH-1955 acquisition landing
# page uncrawlable for these bots alone. Keep these groups and the `*` group
# byte-identical below their first line; if `*` changes, change all six.
